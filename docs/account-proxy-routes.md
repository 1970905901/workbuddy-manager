# 账号出口线路

管理员可以在账号页为每个账号选择命名出口线路，也可以在添加账号时选择线路。
登录授权、轮询、签到、积分、模型查询、连通性测试、地区注册、试用领取和令牌续期
均使用该账号的绑定。线路被移除或配置无效时，相关请求失败，不会回退到默认出口。

## 配置

**在面板里配**：「设置 → 代理」页面可以新增 / 编辑 / 删除线路，也能批量导入与逐条
测试（测试会显示出口 IP 与归属地）。同一页面还有两个全局项：**全局出口代理**
（面板自己发往腾讯的请求走它，存在面板设置里、覆盖 `WB_HTTP_PROXY`）与
**更新下载代理**（一键更新下载发布包时用，只认 http/https）。

### 会话模板：给每个账号一个独立 IP

住宅代理的**会话名写在用户名里**，而「一个会话名 = 一个粘性出口 IP」。所以线路地址
支持一个占位符 `{account}`：

```json
{ "proxies": { "px-cn": "socks5://用户_c_CN_city_Shanghai_s_{account}:密码@网关:10000" } }
```

- **写 `{account}`（独享）**：每个绑定账号渲染成自己的会话名 → **各自一个住宅 IP**，
  账号之间不共享出口（推荐默认）；
- **不写（共享）**：所有绑定账号用同一条会话 → **共用一个出口 IP**（省 IP 额度，
  但同一 IP 上挂多个号，上游按 IP 聚类时容易互相关联；绑到 3 台以上界面会提示）。

会话名在**绑定那一刻**生成并存进账号文件（`proxy_session`），所以之后改昵称**不会**
悄悄换掉出口 IP；要换 IP 用界面上的「换会话」（新会话名 = 新 IP，立即生效）。
昵称是中文时无法直接当会话名（住宅代理的用户名通常只认 ASCII），会退回账号 ID 前缀，
可以在绑定抽屉里改成好记的名字。

### 线路池与权重

一个账号可以同时绑**多条**线路（绑定抽屉里勾选多条即是池）：请求按**权重**分摊、
并在粘性窗口（`WB_PROXY_STICKY_SECONDS`，默认 30 分钟）内固定走同一条 —— 一会儿换
一个出口在风控眼里就是特征。权重写在地址旁边：

```json
{ "proxies": { "px-a": {"url": "socks5://…", "weight": 30}, "px-b": "socks5://…" } }
```

权重缺省 100（越大越常被选中）；只有一条线路时不必管它。

**也可以直接改文件**：线路表读取自 `WB_UPSTREAM_CONFIG` 指向的配置文件，例如：

```json
{
  "proxies": {
    "route-a": "http://proxy.example:8080",
    "route-b": "https://proxy.example:8443"
  }
}
```

代理地址支持 `http://`、`https://`、`socks5://` 三种写法（socks5 依赖 `socksio`，
已随 `server/requirements.txt` 一起安装）。住宅代理服务商常把参数写在用户名里，
例如 `用户_c_CN_city_Shanghai_s_<会话名>`（国家、城市、会话名）——照抄服务商给的
格式即可；**同一会话名会粘在同一个出口 IP 上**，所以每个实例或每个账号要用不同的
会话名，才能各占一个住宅 IP。

代理地址及认证信息只保存在服务端配置中，账号文件只保存线路名；浏览器取得的
线路列表不包含代理地址或密码。

`WB_DEFAULT_ACCOUNT_PROXY` 可指定新账号的默认线路，空值保持原有出口行为。
显式选择「默认出口」会取消账号绑定；未绑定账号仍遵循 `WB_HTTP_PROXY` 的既有行为，
未设置该变量时直连。配置的默认线路不存在时，添加账号会明确报错。

`WB_HTTP_PROXY` **只作用于公网目标**：内网与本机地址（`127.0.0.1`、私有网段、
`workbuddy2api` / `host.docker.internal` 这类内网名）始终直连 —— 否则配了代理之后，
面板连自己上游的那一跳会被交给代理，直接读不到上游状态。

账号线路表是管理端共享的配置。使用多个上游实例时，各实例应配置相同名称和地址的
线路，账号的读取、写入及重载仍作用于当前选中的分组。

## 上游兼容条件

管理端的腾讯请求由本功能处理；聊天请求及上游后台任务由 workbuddy2api 发出，
需要上游同时支持 `proxies` 配置和账号文件顶层的 `proxy` 字段，并在令牌刷新写回时
保留该字段。原版上游不具备这一支持，仅安装管理端修改不能保证聊天使用绑定线路。

上游**整个进程**的出口代理是另一回事，且开箱可用：给上游容器设 `HTTP_PROXY` /
`HTTPS_PROXY`（以及 `NO_PROXY`）即可，大小写都认 —— 走的是 Go 标准库的代理解析，
作用于上游的全部出站请求（含聊天）。它给不了「每个账号一条线路」，只适合
「整台机器的出网都要过代理」这种部署（issue #136）。

Python 活动任务执行器还需要读取 `WB2A_PROXY_CONFIG` 和账号的 `proxy` 字段，
按账号绑定出口；管理端已将配置文件位置传递给执行器。未适配的执行器不能用于
要求全流程出口一致的账号。

修改线路绑定后，管理端请求当前分组的上游重载。非默认分组没有配置容器名时，
由支持账号热加载的上游读取变更；无法调度重载时，响应的 `reload_triggered` 为 false。
调整线路表本身之后，应重启相关上游实例以重新读取配置。
